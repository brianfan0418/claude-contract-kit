# 合約初審（contract-review）

**AI 初審不取代法務與律師判斷。** 此句須出現在每份初審輸出的開頭。

目標：依公司審閱手冊找出偏離與須升級事項，每一項都能回到原文與手冊核對。

## 不可違反的規則

1. 只審符合 schema 的 Markdown 合約；PDF 須含 `<!-- page: N -->` 標記，Word 等無固定頁碼者以原文條號定位；原檔唯讀。
2. 依據只有兩個來源：合約原文與 `<合約工具包資料夾>/playbook/playbook.md`。每項意見列：條號、頁碼、逐字引句；手冊條款編號與其公司立場原文。不引用記憶中的法條內容；法條只用手冊「參考法條」欄已列者，並標「須法務核對現行條文」。
3. 手冊該項「公司立場」為「待填」時，只列合約原文與條款要點，判斷寫「手冊未填，無法判定」，不自行補立場。
4. 合約沒有某類條款時寫「未載明」，註明全文搜尋所用的標題與用語；是否構成風險交給使用者與法務，不寫「缺漏」「不合理」之類結論。
5. 區分「事實」（原文怎麼寫）與「判斷」（與手冊比較的結果），判斷欄明確標示。不使用「應該」「通常」「大概」這類沒有依據的語氣。
6. 輸出寫入檔案前，交給不帶前情的對話逐條回原文核對所有引句；不符的意見不得出現在最終版本。

## 步驟

1. 確認本公司在合約中的角色（買方、賣方、承租人、出租人、授權方、被授權方）；手冊依角色分列時依此選用。角色不明時詢問使用者。
2. 依手冊條款順序逐項處理：期間與續約、終止、付款、責任上限、賠償、保密、智慧財產、個資、準據法與管轄、不可抗力、轉讓，再加上手冊後續新增的條款。每項在合約全文搜尋相關條文（標題與關鍵詞），都找到後才下結論。
3. 每項輸出：

   | 手冊條款 | 合約條號與頁碼 | 原文（逐字） | 手冊公司立場 | 判斷 | 理由與建議修改 |
   |---|---|---|---|---|---|

   判斷只用：符合、偏離（在可接受範圍內）、偏離（須升級）、手冊未填無法判定、合約未載明。「偏離」須引用手冊的可接受範圍或升級條件原文作為依據。
4. 另列「手冊未涵蓋但值得注意」：只列原文中的事實（例如單方變更條款權、獨家、最低採購量、違約金、單方解釋權），每項附出處，標為「提請法務確認」，不下偏離判斷。
5. 合法性初審：僅就手冊「參考法條」欄列出的法條，說明合約條文與該法條所涉事項的對照（引原文與法條條號），一律標「須法務核對」；不得斷言某條款無效或違法。
6. 總結：偏離（須升級）的項目清單置頂；其次是手冊未填項目數。寫入主檔時（`risk_level`、`last_review_date`）須經使用者確認，且由 `<合約工具包資料夾>/build_register.py` 從 Markdown frontmatter 產生，不直接改 `register.csv`。
7. 獨立核對：交給不帶前情的對話：「逐一確認每段引句逐字出現在所指檔案所指頁，以及手冊引文與 playbook.md 一致；列出不符者」。不符者修正後重新核對，核對結果附在輸出末。

## 每份輸出的開頭

「AI 初審不取代法務與律師判斷。以下意見依審閱手冊（版本：<手冊版本>）與合約原文產生，引句已由獨立對話核對。」
